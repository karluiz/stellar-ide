# Product

<!-- impeccable:product-schema 1 -->

## Platform

adaptive

## Stack

Native desktop application written in C++20 with the Raven C/C++ GUI library and CMake. Claude Code CLI and Kimi Code CLI are the supported agent harnesses. The initial target is Linux/X11; Raven retains Windows and macOS support.

## Users

Software developers working across several related repositories who want Claude Code or Kimi Code sessions, reusable agent definitions, and project knowledge in one workspace.

## Product Purpose

Provide a simple agentic IDE where a developer prompts one lead agent, watches subagents work, and turns useful outcomes into durable workspace knowledge. Success means starting a real Claude Code or Kimi Code run, understanding its agent activity, and reviewing proposed wiki updates without leaving the app.

## Positioning

A workspace is a root containing repositories and a peer wiki. Agents are editable code, not database records; each harness's native subagent mechanism drives the same live multi-agent view. The wiki combines human-readable Markdown with a typed, provenance-bearing neurosymbolic knowledge graph and bounded episodic run memory, all subject to human review rather than opaque agent memory.

## Operating Context

The developer opens a workspace root, selects Claude Code or Kimi Code, works in its repositories, defines agents in `.agents/agents/`, and maintains Markdown notes in `wiki/`. Each harness supplies its own authentication, permissions, tools, sessions, and subagent behavior. Kimi loads the shared agent definitions through `--agent-file`; Stellar converts the same Markdown to Claude's `--agents` JSON at launch. Agents use `raven-ide-knowledge` to query graph context and stage graph writes for review. Successful lead runs also stage session episodes for human review; accepted memories can inform later lead prompts.

## Capabilities and Constraints

- The simplified header contains the workspace, Files/Panels folding controls, a paired appearance toggle, and run state. Header text is bounded with full tooltips; above 150% interface zoom the workspace/run labels hide and both sidebars fold automatically to preserve navigation, restoring their previous visibility when zoom decreases. Center tabs are Agent (0), Editor (1), Endurance (2), More (3), and Review (4); More groups Definitions (0), Settings (1), Memory (2), and Worktrees (3). Endurance groups Canvas, YAML, Runs, and the existing Live delegation graph. Right tabs are Run, Wiki, Graph, Log, and Step. `Ctrl+M` opens Memory Universe, `Ctrl+K` opens Knowledge, `Ctrl+Shift+D` opens Code Review, and `Ctrl+,` opens or closes Settings. Settings keeps Appearance and Agent Workspace visible while Notifications and Keyboard/Shortcuts stay collapsed until needed. `Esc` returns to the previous workspace.
- Claude Code and Kimi Code are supported and selectable before a run; no other harnesses are supported.
- One setup icon or `Ctrl+Shift+E` opens a compact Run setup popover containing model, reasoning effort, harness, and mode; the composer otherwise shows only setup, Recall, and Send icons. Model and effort selections persist independently for each harness. Claude offers Default, Sonnet, Opus, and Haiku with Default/Low/Medium/High/XHigh/Max effort through `--model` and `--effort`. Kimi offers its configured default, K2.8 Preview, K2.7 Code Highspeed, K3, K3-256k, K3.1 Pro, and K3.1 Pro Highspeed with Default/Low/High/Max thinking through ACP `session/set_config_option`. Selections persist per workspace and lock during active work.
- Activity shows a per-run receipt. Claude's reported `total_cost_usd` is displayed as an exact dollar amount with input (including cache creation/read) and output tokens; Build runs add the knowledge curator's reported usage to the lead total and update the same persistent Alerts receipt. Kimi's ACP response does not document per-run dollar cost, so Stellar labels it `not reported` rather than estimating charges or membership quota.
- Workspace-local conversation threads are stored atomically in `.stellar/threads.json`. New chat (header or Ctrl+N) clears the current transcript without deleting history. Threads persist user/assistant messages, title, harness, transcript, resumable session ID, and archive state; startup restores the latest active thread and selecting a thread resumes its session on the next prompt. The Chats header switches between Active and Archived views, archives the selected conversation, and restores archived conversations with their full history. Empty chats are not added, switching or archiving is blocked during active runs, and each workspace has independent history.
- One lead session starts each run and resumes on follow-ups; native subagents from either harness appear in the live Activity panel and the Endurance → Live graph. Kimi lead sessions use ACP to stream answer chunks into Orchestrator messages; thought chunks update a persistent THINKING pending state and status strip without rendering private reasoning. Claude uses its native partial-message stream. A pending message appears before workspace preparation, advances through STARTING and CONNECTED, remains throughout model reasoning, and clears only for visible answer or tool activity. Each run groups tool calls into one collapsed Work activity expander with readable step names, concise paths/commands, and textual state instead of printing every call and output as a chat message. Coding prompts require inspection, implementation, and relevant build/test verification before the final summary.
- Endurance orchestrates reusable multi-agent missions from `endurance/*.yaml`. A strict versioned schema defines agent and approval steps, dependencies, harness/model/effort inheritance, Build/Ask/Review modes, timeouts, retries, positions, task input, and optional Git-worktree isolation. Canvas and YAML edit one validated model with atomic saves, cycle/missing-agent/parallel-Build prevention, duplicate-ID checks, and bounded outputs. Narrow workspaces use a readable vertical DAG without changing saved coordinates. Runs execute an immutable snapshot through real Claude Code or Kimi Code processes with dependency scheduling, read-only concurrency up to four, serialized builds, human gates, Stop/Resume, retry budgets, timeout handling, and recovery after shutdown. `--endurance` opens the module and `--workflow-task TEXT` starts a manual run; the command palette also exposes it.
- Endurance runs and their 64 KiB-per-step outputs, events, usage, checkpoints, and workflow snapshots persist under `.stellar/endurance/runs/`, retaining the newest 100. Build steps use the normal checkpoint and Review flow; worktree steps use the existing isolated-mission flow. Successful workflows stage one episode for human knowledge review rather than one per step. Recurrence is an optional cron trigger with local/UTC time, overlap `skip|queue`, missed-run `skip|run_once`, a required default task, and persistent next-run state in `.stellar/endurance/schedule.json`. Runs and approvals open from notifications.
- While the lead or knowledge curator is active, `Ctrl+Enter` queues one follow-up in a visible composer bar instead of rejecting it. The bar distinguishes active lead work, active knowledge review, lead failure, and a pending Wiki decision; when a proposal blocks the queue, a Review Wiki action opens it directly. Cancel removes the follow-up, Stop cancels both current and queued work, and a failed lead run leaves the queue paused. Successful work starts the queued prompt after knowledge review, or immediately after the user resolves a pending proposal. Retry repeats the last prompt in the same session after a lead failure. The header and Activity card expose elapsed time and the current action with four timer wakeups per second rather than animation-rate redraws; elapsed time continues throughout knowledge review. Completed and failed lead runs issue Linux desktop notifications through `notify-send`. Verification failures, knowledge review readiness, and mission applies also notify with the Stellar icon; autosave failures use critical notifications throttled to one per minute. `.stellar/notifications.json` retains the newest 50 events in an Alerts view with Open destination and Clear actions. Do Not Disturb and per-type Settings switches filter only desktop alerts; all events remain in the in-app history.
- The composer offers Build, Ask, and Review modes, also selectable with `--mode build|ask|review`. Build preserves coding, verification, checkpoints, and memory curation. Ask performs read-only answers and Review produces read-only findings; neither creates checkpoints, episodes, or wiki proposals, and slash commands require Build. Mode changes start a fresh lead session and are locked during active work.
- Recall is a workspace-local prompt library opened from the composer history icon or `Ctrl+R`. It imports user prompts from existing chats once, records prompts after successful launches, deduplicates exact trimmed text, and ranks pinned prompts first followed by reuse count and recency. Search, Enter-to-reuse, Pin/Unpin, and confirmed Forget actions are available; restoring fills the composer without submitting. Up to 200 unpinned prompts and 20,000 characters per prompt persist atomically in `.stellar/recall.json`, with no network or model involvement.
- With Kimi selected, the composer provides native slash completion for common commands and project/user Skills, including `/skill:name` and `/name` forms. Slash prompts bypass the ordinary prompt prefix so Kimi executes them as commands. `@` completes workspace-relative files through nested directories; an attachment selector shows per-file and total approximate token budgets, with Remove and Clear actions that preserve the remaining prompt. Compact keeps the original task plus up to six recent messages for the next fresh session while leaving the full visible thread unchanged. Validated text mentions up to 512 KiB are embedded as ACP resources, other files become resource links, and Claude receives explicit file references. Build output, VCS metadata, dependency directories, symlinks, and outside paths are excluded.
- `Ctrl+Shift+P` opens a command palette for application actions and run modes, `Ctrl+Shift+O` opens workspace files by name, and `Ctrl+Shift+F` searches text across workspace files. Content results show `path:line` and open directly in Editor; searches are case-insensitive, debounced by 250 ms, capped at 80 results and 2 MiB per file, and exclude Stellar state, VCS metadata, build output, dependencies, binaries, and symlinks. The overlay supports arrows, Enter, and Escape and remains bounded at 200% zoom.
- Ordinary agent runs create persistent task checkpoints under `.stellar/checkpoints/`. The Review tab separates Code changes from Knowledge, with checkpoint history, per-file added/modified/deleted diffs, and Open file navigation. A nested Verification view records recognized build/test commands, their passed/failed state, and bounded output alongside each checkpoint; parsed C/C++, Python, and Rust diagnostics can reopen the source at the reported line. Rerun executes a recorded command asynchronously and updates the same checkpoint. Watch mode reruns the selected check one second after autosave, without overlapping runs, and can be enabled with `--watch`. Verification-only runs remain reviewable even when no files change. Snapshots exclude Stellar state, VCS metadata, build output, dependency directories, and symlinks; they cover up to 12,000 files and 128 MiB with a 2 MiB per-file limit, and partial coverage is labeled. Restore requires confirmation and validates every affected file against the run result before changing anything, so later work is never silently overwritten. Individual text hunks can also be restored; applied hunk IDs persist so partial and later full restores operate only on remaining changes. File-bearing Work activity rows open the editor, including `path:line` navigation when available. `Ctrl+Shift+D` opens Code Review.
- More → Worktrees creates isolated Git worktrees under `.stellar/missions/` for Build-mode runs in the workspace root or direct child repositories. Shared agent/wiki context seeds the worktree but is excluded from patches; Stellar state and untracked binary artifacts never cross back. Mission diffs include tracked and untracked text changes, with a 2 MiB display cap. Apply requires confirmation and `git apply --check`, preserves conflicting user work, creates no commit or merge, and is blocked after one success. Individual hunks can be applied independently, with `applied_hunks` persisted so later selections and full applies include only remaining changes. Applied state persists, and Return keeps unapplied work isolated until the user explicitly applies or discards it; destructive discard also requires confirmation.
- Agent definitions are Markdown files with YAML frontmatter under `.agents/agents/` and can be created with `Ctrl+Alt+A`, edited, and deleted in the app. Custom deletion requires confirmation and stays inside the shared agent directory; the built-in `orchestrator`, `code-reviewer`, and `wiki-curator` cannot be deleted. Both harnesses use this single source; legacy `.claude/agents/` files migrate automatically without overwriting shared definitions.
- The workspace contains multiple repositories, an initial root, and `wiki/` alongside them.
- A native file tree explores the entire workspace. The Editor tab opens text files with language detection, line numbers, soft wrapping, dirty-state tracking, and atomic saves. Source files, agent definitions, and wiki notes autosave after 900 ms without reloading the editor or moving the caret; failed saves retain the dirty state and retry after 5 seconds. Pending edits flush before agent runs, restores, proposals, and workspace changes, while `Ctrl+S` and the Save buttons remain immediate manual actions. `.stellar/recovery.json` stores editor backups immediately and drafts after a debounce; startup restores only exact saved-content matches, preserves conflicting disk changes, and offers Retry for interrupted runs. Files are limited to 2 MiB and validated against the workspace boundary. `--open-file` opens a file at launch.
- The wiki is an Obsidian-like Markdown editor with backlinks and `[[wiki links]]`.
- `wiki/graph.jsonl` stores typed entities and relations with provenance and confidence, including accepted `episode` records with `memory=episodic`, task, session ID, harness, status, and a bounded transcript.
- Successful runs stage one episode with a maximum 16,000-character transcript. Staged episodes join the existing human-reviewed graph proposal and never enter persistent memory without acceptance.
- After a completed run, Markdown and graph changes are merged into one reviewable proposal. Staged graph writes persist across app restarts and are only applied after acceptance. Accepted episodes upsert by `run:<session>`, so follow-ups update rather than duplicate session memory. Accepted records can also be forgotten from Knowledge or Memory Universe after confirmation; deleting an entity removes its touching relations, writes `graph.jsonl` atomically, and leaves staged proposals untouched.
- `knowledge_context` blends lexical ranking with optional deterministic local vector recall: hashed token and character-trigram features use cosine similarity entirely offline, improving morphological paraphrase matches without neural embeddings, model downloads, or semantic-AI claims. A Settings switch restores lexical-only matching. Accepted episodes and one-hop graph context can inform later lead prompts; `depends_on` relations support bounded transitive inference. Episode transcript output is capped around 3,000 characters for recall while the full bounded record remains in `wiki/graph.jsonl`. Automatic consolidation is not performed.
- `raven-ide-knowledge` provides stats with an `episodes` count, context, entity/relation listing, an `episodes` JSONL listing, and staged writes. New graph records only enter through acceptance in Stellar; `forget ID` is the explicit immediate deletion command for accepted records.
- Memory Universe opens under More with `Ctrl+M` and presents reviewed data only: accepted episodes are inner planets, other accepted entities form outer systems, and only real graph relations become links. Empty state text explains that a run's episode must be accepted; no records are fabricated and no external assets or dependencies are added.
- The Universe canvas provides a theme-aware workspace black hole, deterministic stars, Fit, drag panning, wheel zoom, keyboard arrow/+/-/0 navigation, hover, and selection. Its details panel exposes provenance, metadata, relations, and transcript content, and appearance switches restyle the canvas. These visualizations do not imply neural embeddings or vector search.
- While Memory is visible, `MemoryUniverse::advance(delta, reduce_motion)` drives native animation at a capped 30 FPS: slow differential orbital speeds, a subtle radial gravitational tug, rotating accretion particles, and a lensing pulse. A shared timed main-loop scheduler requests paint-only redraws without invalidating layout. Reduced motion stops the animation, hidden tabs do not continuously redraw, and no data changes occur.
- The first version does not provide a full source-code IDE, Git client, terminal emulator, or additional harnesses.
- A cinematic opening presents Dylan Thomas's complete six-stanza `Do not go gentle into that good night` beside the procedural Gargantua, using local fonts and no external imagery. Stanzas reveal in reading order and the complete poem remains until the reader activates the bottom-right Skip button, clicks, or presses Enter, Space, or Escape; `--prompt` bypasses it. Reduced motion shows the static complete composition and still waits for Skip. Opening redraws stop after the attribution settles, and dismissing restores composer focus. An original locally generated instrumental score plays through SDL2 with gentle fades and no generation-time runtime or network dependency. A keyboard-accessible bottom-left speaker control mutes/unmutes it and persists the preference; Skip fades the audio, and `--prompt` never starts it. Generation prompt, seed, model, and non-commercial weight-license provenance are included rather than presenting the output as guaranteed copyright clearance.
- Five Interstellar appearance families provide fifteen variants: Earth Dark/Light/Glass, Miller Dark/Light/Glass, Mann Light/Dark/Glass, Edmunds Light/Dark/Glass, and Gargantua Dark/Light/Glass. Earth Dark is the default. Ledger and High Contrast themes are disabled and are no longer loaded or selectable. Glass uses Raven's native frosted material with planet-tinted wallpaper and coordinated composer, Activity, and proposal surfaces; Glass variants keep work surfaces neutral, reserve stronger tint for actionable proposals, use a single composer boundary with outer-opacity focus feedback, and keep structural tabs and lead messages flat. It does not make the window transparent. Header and Settings actions switch each family between Dark and Light, or from Glass to Light. Launch selection supports `--theme earth|earth-light|earth-glass|miller|miller-light|miller-glass|mann|mann-dark|mann-glass|edmunds|edmunds-dark|edmunds-glass|gargantua|gargantua-light|gargantua-glass`. Theme changes preserve the active session and restyle existing transcript messages, Activity markers, agent-kind labels, status labels, graph nodes, and theme-linked structural Border outlines. Explicit `BorderColor` and `Rborder_set_outline` colors remain fixed.
- A compact status-bar theme button with live planet artwork and the current theme name opens a full-window `Choose your world` carousel by click or `Ctrl+Shift+T`. One large central high-fidelity mockup of Stellar is flanked by smaller, dimmed rectangular previews; horizontal translation, scale, and opacity create depth without skewing their content. Each mockup uses the candidate theme's actual XML palette to render readable navigation, conversations, transcript copy, a Memory Universe scene, Activity, composer, and status bar; Glass previews also use native frosted material. A native Vulkan fragment shader renders every planet at display resolution with spherical lighting, atmospheres, distinct terrain, and real rotation. Each world adds a distinct animated phenomenon: Earth's independent cloud systems, shadows and satellite; Miller's traveling large swell, ripples and evolving foam; Mann's snow clouds, polar aurora and satellite; and Edmunds' dust storms, haze and satellite. Gargantua is a transparent procedural 3D black hole with bent light rays, a turbulent accretion volume, a dark event horizon, Doppler-brightened emission, lensed disk structure, and slow camera drift; it uses no photographic texture or rectangular overlay. Left/Right arrows, Previous/Next, side-preview clicks, and cooldown-limited scroll browse families; Up/Down arrows and explicit Dark/Light/Glass buttons choose the finish. An exponential deck transition and GPU planet motion stay within a 30 FPS application cap; reduced motion keeps previews static and snaps directly to the selection. The compact status-bar artwork remains static to avoid continuous background redraws. Settings opens the same gallery. Selection applies and persists immediately without closing it. Compact spacing preserves every control through 200% zoom, and Escape or Close returns focus to the current-theme button. Every world, including Gargantua, is procedural and requires no external imagery.
- Left Chats/Files/Agents/Wiki tabs show one full-height navigation list at a time, with search filtering conversations, agent definitions, and wiki notes but not the Files tree. The center keeps a constrained transcript and floating composer. The right Run/Wiki/Graph/Log/Step panel is visible by default with Run selected; its Open mission control action reveals Endurance → Live once delegated work exists. Both sidebars fold independently from header controls, `Ctrl+B`, and `Ctrl+Shift+B`.
- `.stellar/profile.json` atomically persists interface/editor zoom, theme, harness, run mode, per-harness model/effort, sidebar visibility, vector recall, watch checks, opening-sound preference, notification preferences, and custom shortcuts. Explicit `--theme`, `--harness`, `--mode`, and `--watch` options override saved values at launch. Settings captures custom shortcuts with Ctrl, Alt, or Super required, rejects duplicates and reserved editor combinations, disables replaced defaults, and restores defaults on Reset; changes save immediately.

## Accessibility & Inclusion

The interface starts at 115% scale and supports editor-only and whole-interface zoom through 200%, keyboard navigation for core workflows, and paired dark/light variants for every Interstellar planet. All ten themes meet at least 4.5:1 contrast for body, muted, and placeholder text on their working surfaces. High zoom preserves navigation through compact header behavior, automatic sidebar folding, and the world carousel's reduced padding and preview minimums. `Ctrl+M` opens Memory Universe, where arrow keys pan, plus/minus zooms, and 0 fits the canvas; `Ctrl+K` remains the Knowledge shortcut. `Ctrl+Shift+T` opens the world gallery, and Escape dismisses it with focus returned to the current-theme button.

## Brand Commitments

Use a dense mission-control working screen: repositories and agents on the left, conversation in the center, and live subagent activity and wiki on the right. The visual tone should be precise, restrained, and dark.

## Evidence on Hand

Raven source and examples are available under `third_party/Raven/`. Claude Code and Kimi Code are installed locally. No existing product assets, user research, screenshots, or usage data were provided.

## Product Principles

1. The filesystem is the source of truth for agents and knowledge.
2. One clear lead session is simpler than manual orchestration.
3. Agent activity must be visible without exposing implementation noise.
4. Knowledge changes require human review.
5. Native, keyboard-friendly operation takes precedence over decorative interface behavior.
6. Episodic memory is bounded, inspectable, session-stable, and never written without human acceptance.
